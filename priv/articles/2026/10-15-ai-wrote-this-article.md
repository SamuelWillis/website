## Notes

Running LLMS locally requires having a computer and inference software.

The amount of available RAM (and/or VRAM) you have dictates what models you can run.

Inference is the process of serving LLM predictions in real time without
updating the model weights.

I am going to focus on running LLMs on Apple Silicon with [llama.cpp](https://github.com/ggml-org/llama.cpp)

There are other options like Ollama and vLLM but I wanted to learn a little more about
serving the LLMs and configurations.

### Choosing a model

There's lots of models and they are often offered in multiple "sizes".
The sizes balance training parameters with precision.

These sizes are based around number of _parameters_ and the bytes-per-parameter
the model uses.

_Parameters_ are the values the model learnt during training.
These parameters mainly consist of _weights_ (how important a word is) and
_biases_ (adjustments to final predictions to better match patterns learnt).
The more parameters, the better the model can store patterns and nuance.

A poorly trained model with lots of parameters can be much worse than a well trained
model with fewer parameters. Bigger is not always better.

Models typically store their parameters, which are numbers, as 32-bit floats.
If you have 7B parameters, this takes a lot of space.

So models are often offered at differnt _quantization levels_.
The level specifies the chosen bit-width for the parameters.
Reducing the preceision of the parameters greatly reduces the memory required,
often without a massive reduction in accuracy and quality.

There's lots of different _quantization_ techiniques and they don't involve simply
truncating the parameters.
One is called _GGUF_ which is llama.cpp's desired format for the model.

Choosing a good blend of parameter size and quantization level is key to getting
good and accurate performance out of the LLM.

Finally, there's the hardware itself to consider. These things take space and if
your computer doesn't have a lot of juice then some models will be out of reach.

**Note:** Apple Silicon uses a unified memory architecture (UMA) which means that the
GPU and CPU share the same memory pool.
Unlike discrete‑GPU setups you’re not limited to the VRAM on the card, allowing
larger models.

#### How big of a model can I run?

There's a rough formula but you need to make sure you leave space for the OS etc.

On Macs you want about 4GB left over for the OS.

Here's a rough formula:
```
Memory(GB) = P * Z * 1.2 

Where:

    Memory = GPU memory allocated for model, expressed in Gigabytes
    P = Model (parameter) size in Billions
    Z = Quantization factor in Bytes (1 Byte = 8 bits) - see below
    1.2 = Represents a 20% overhead for loading additional data into GPU memory
```

Through some examples we can see how much of an impact in memory requirements the
quanitization level has:

```
70B parameters at F16:

Memory(GB) = 70 * (16 bits / 8 bits per byte) * 1.2
           = 70 * 2 * 1.2
           = 168

70B parameters at Q8:

Memory(GB) = 70 * (8 bits / 8 bits per byte) * 1.2
           = 70 * 1 * 1.2
           = 84

70B parameters at Q4:

Memory(GB) = 70 * (4 bits / 8 bits per byte) * 1.2
           = 70 * 0.5 * 1.2
           = 42
```

There's fancier formulas but this is a good litmus test.

[This is a nice guide](https://github.com/ggml-org/llama.cpp/discussions/25065)

### Running the models

Okay, we've found a model and we're ready. How do we run the dang things.

First install llama.cpp. I did via curl, as per their recommendation.

From there, there's a couple choices.

You can run the model as an interactive chat with [llama cli](https://llama.app/docs/cli).

#### How about with agents?

We want to _serve_ the model so that the agent can send its stuff over to it.
So we need [llama serve](https://llama.app/docs/quickstart#serve-a-model).

There's a _ton_ of options for this but an good launch point from [pi.dev](https://pi.dev/docs/latest/llama-cpp#start-the-router) is roughly:

```bash
llama-server \
  --models-dir ~/models \
  --no-models-autoload \
  --jinja \
  --host 127.0.0.1 \
  --port 8080 \
  -ngl 999 \
  -c 32768
```

There's a couple things to keep in mind for Macs.

1. Make sure llama was built with [metal enabled](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md#metal-build)
2. Set the ngl to a big number so you can use your GPUs
3. The context size (`-c`) has a fairly good impact of the amount of memory needed, so tweak as needed.

## AI Wrote this part

Running large language models (LLMs) on your own Mac is possible with **llama.cpp**, a lightweight inference engine that works on Apple Silicon.
An LLM is a huge table of numbers that the computer uses to generate text.
To fit a model on a laptop, you pick a **model size** that fits your memory and can shrink the numbers further with **quantization**—e.g., 4‑bit or 8‑bit precision—so the table takes less space but still sounds good.

On macOS you can estimate the memory a model needs with

```text
Memory (GB) ≈ (parameters × bits / 8) × 1.2
```

(The 1.2 adds a 20 % safety margin).
For example, a 1 B‑parameter model at 8‑bit precision uses about

```
1 B × (8 bits / 8) × 1.2 ≈ 1.2 GB
```

So a 1 GB model comfortably fits on a Mac with 8 GB of RAM.

Once you have the right model file (`*.gguf`), install `llama.cpp` (e.g., via `curl`), load the model, and run inference from the command line or embed it in an application.

> **Quick start**
> ```bash
> curl -L https://github.com/ggerganov/llama.cpp/releases/latest/download/llama.cpp.tar.gz | tar xzf -
> cd llama.cpp
> ./main -m models/ggml-base-1b.gguf
> ```
> Replace `ggml-base-1b.gguf` with any other GGUF model you downloaded.
